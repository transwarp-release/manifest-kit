# GitLab → 扫描平台 → GitHub 正常发布测试

## 目标和输入

用本仓库测试已有平台是否能够拉取 GitLab 项目，扫描病毒、漏洞、敏感信息及 skill 风险，随后发布到 GitHub。

本例只包含应当正常放行的源代码和普通文本数据。不包含病毒样本、测试病毒字符串、真实凭据、仿真令牌、恶意 skill 或故意引入的脆弱依赖。本例不定义发布平台的接入协议、配置检查或拒绝分支。

将仓库根目录的文件提交到指定 GitLab 项目。提交范围包括隐藏文件 `.gitignore` 和 `.gitattributes`，不包含 `.local/` 及本地验证工具。记录本次来源分支和提交 SHA，交给平台的输入使用 GitLab 项目地址。

## 发布前本地检查

在拉取到的仓库根目录执行：

```text
python -B -m unittest discover -s tests -v
python -B scripts/run_demo.py
```

两条命令均应返回 `0`，测试应全部通过。示例报告应包含 4 个文件，`verification.json` 和 `comparison.json` 的 `status` 均为 `match`。`cache/session.tmp` 是普通临时文本，按示例排除配置不进入清单。

## 平台正常路径测试用例

| 编号 | 操作 / 观察点 | 预期结果 | 建议留存的证据 |
| --- | --- | --- | --- |
| GL-GH-01 | 将指定 GitLab 地址交给现有平台 | 成功取得约定分支/提交，目录完整，中文文件路径正常 | 来源地址、分支、提交 SHA、拉取日志 |
| GL-GH-02 | 执行平台病毒扫描 | 无病毒检出或病毒阻断 | 病毒扫描报告、扫描器及规则版本 |
| GL-GH-03 | 执行平台漏洞扫描 | 完成适用扫描，无阻断项；仓库第三方运行/测试依赖数为 0 | 漏洞报告及适用的代码扫描结果 |
| GL-GH-04 | 执行平台敏感信息扫描 | 无真实账号、密钥、令牌或公司业务数据检出 | 敏感信息扫描报告 |
| GL-GH-05 | 执行平台 skill 风险扫描 | 两份 `SKILL.md`、各自脚本和引用文档均被覆盖，无阻断项 | skill 清单、扫描覆盖范围和结果 |
| GL-GH-06 | 由平台完成 GitHub 发布 | 发布成功；应用、skill、示例、测试、许可证及隐藏配置文件齐全 | 平台任务状态、目标仓库地址/提交、来源映射 |
| GL-GH-07 | 从发布后的 GitHub 源码运行上述两条本地命令 | 测试通过，示例校验与清单比对都为 `match` | 消费端运行日志、示例报告 |
| GL-GH-08 | 比较来源与发布内容 | 与来源提交对应的文件字节相同；平台主动变更的元数据可被说明和追踪 | 来源/目标版本及文件比较记录 |

如果平台的漏洞扫描仅覆盖依赖，本例中依赖项为零应解释为“无第三方依赖可检查”，不能把“未执行的源码扫描”记为通过。GitHub 标签和 Release 按平台现有发布方式验收，此项目没有额外要求。

扫描器有告警时，应保留实际告警并评估，不预设为误报。本地单元测试通过不替代任何一类平台扫描。

## 验收记录建议

记录执行日期、平台任务编号、来源提交、四类扫描结论、GitHub 目标位置、最终状态和消费端运行结果。四类扫描和实际发布尚未执行前，记录为“待执行”，不要填为通过。
